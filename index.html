Node.js + TypeScript

A tiny database.
On the other end of a socket.

basewire is a lightweight key-value database for Node.js. Run a server, connect with a typed client, and read or write values over WebSocket.

Start building → API reference
app.ts 
import { DatabaseClient } from "basewire";

const client = new DatabaseClient({
  url: "localhost",
  port: 8080,
  auth: process.env.DB_AUTH,
});

await client.connect();

const users = client.createDatabase("users");

await users.set("u_1", {
  name: "Ada",
  role: "admin"
});

→ connected to ws://localhost:8080

Why basewire

Small surface area. Intentionally.

01

One socket

Connect once and create as many isolated database handles as you need.

02

Typed values

TypeScript generics keep your database values typed from creation through reads and writes.

03

Optional validation

Attach a Zod schema when you need runtime validation. Nothing extra when you don't.

Quickstart

From zero to storage.

Install the package, start the server, and connect a client. That's the whole setup.

01

Install

Add basewire to your Node.js project.

terminal 
$ npm install basewire zod
02

Start a server

One process handles connections and storage.

server.ts 
import { DatabaseServer } from "basewire";

new DatabaseServer({
  port: 8080,
  auth: process.env.DB_AUTH,
});
03

Connect

Connect first, then create database handles.

app.ts 
import { DatabaseClient } from "basewire";

const client = new DatabaseClient({
  url: "localhost",
  port: 8080,
  auth: process.env.DB_AUTH,
});

await client.connect();

const users = client.createDatabase(
  "users"
);

await users.set("u_1", {
  name: "Ada",
  role: "admin",
});

const ada =
  await users.get("u_1");
Runtime safety

Give your database a shape.

Pass a Zod schema when creating a database and basewire uses it to validate writes at runtime while TypeScript infers the corresponding value type.

No schema? No runtime validation.
Schema provided? Values are checked before transport.
Each database path can have its own schema.
users.ts 
import { z } from "zod";

const User = z.object({
  name: z.string(),
  role: z.enum([
    "admin",
    "member"
  ]),
});

const users =
  client.createDatabase(
    "users",
    User
  );

// validated before transport
await users.set("u_1", {
  name: "Ada",
  role: "admin",
});
Reference

API reference

Everything you need to work with clients, databases, servers, and validation.

DatabaseClient

Represents the WebSocket connection to a basewire server.

new DatabaseClient(options)

Constructor

Property Type Description
url string Server hostname or URL.
port number Server port.
auth string Authentication token.
secure boolean? Use secure WebSocket transport.

Methods

connect(): Promise<void>

Opens the WebSocket connection and authenticates the client.

createDatabase<T>(path): Database<T>

Returns a database handle for the specified path.

Events

"error"

Emitted when a socket or request fails.

"disconnected"

Emitted when the socket connection drops.

Database<T>

A handle to a single database path.

get(key): Promise<T | null>

Returns the value or null when the key doesn't exist.

set(key, value): Promise<T>

Stores a value and returns the stored value.

has(key): Promise<boolean>

Checks whether a key exists.

delete(key): Promise<boolean>

Deletes a key and reports whether something was removed.

all(): Promise<{ [key: string]: T }>

Returns all key/value pairs.

Batch operations

getMany(keys)
setMany(data)
deleteMany(keys)
batching.ts
await users.setMany([
  {
    key: "u_2",
    value: { name: "Grace" }
  },
  {
    key: "u_3",
    value: { name: "Alan" }
  }
]);

const values =
  await users.getMany([
    "u_1",
    "u_2"
  ]);

DatabaseServer

The process responsible for storage and WebSocket connections.

new DatabaseServer(options)
Option Type Description
port number Port to listen on.
auth string Authentication token.
ssl SSLOptions? Enables secure WebSocket transport.
onStdout function? Receives server log lines.
server.ts
import { DatabaseServer }
  from "basewire";

new DatabaseServer({
  port: 443,
  auth: process.env.DB_AUTH,

  ssl: {
    key: readFileSync("key.pem"),
    cert: readFileSync("cert.pem")
  }
});
